1. Purpose and Scope

Purpose: Provide an execution-ready SOP for upgrading Versa instances in AWS from their current instance type to a larger or smaller instance type e.g cx4xlarge to cx8xlarge or vice versa. This SOP is designed for engineering execution across US, EMEA, and LATAM regions and ensures a consistent, validated process for all teams.

Applies to: Versa VOS devices running in AWS environments (MCBB scope and applicable regional environments).

Out of scope: Non-Versa devices; non-AWS environments; unrelated MCBB components.

2. Critical Governance Control: Templates vs CLI (Non-Negotiable)

Policy Statement (MANDATORY): All persistent configuration changes MUST be performed through Versa Director template updates and pushed centrally. Direct CLI configuration is PROHIBITED except during an ACTIVE INCIDENT requiring immediate service restoration.

Reason: The next template push will overwrite local (CLI) settings, causing silent regression and drift.

Incident Exception (ONLY during active incident): CLI actions may be used to restore service immediately. After stabilization, the same changes MUST be applied to Versa Director templates and re-pushed to affected device groups. Post-incident reconciliation is REQUIRED to eliminate drift and prevent regression.

3. Pre-Change Validation Checklist

Complete ALL items before starting the instance type change.

·       Confirm AWS console access with appropriate IAM permissions to stop/start EC2 instances and modify instance types

·       Obtain the Versa checklist and cross reference [link to be provided here] - do not proceed without it

·       Confirm maintenance window with your regional lead and notify stakeholders

·       Identify the target Versa instance(s) for your region in the AWS Console (EC2 -> Instances)

·       Record the current instance type for rollback reference

·       Confirm instance health: no active alarms, both status checks passing (2/2)

·       Confirm no active sessions or critical traffic is running through the instance

·       Take an AMI snapshot/backup of the instance before proceeding

·       Validate that Versa Director templates are current and no pending pushes are outstanding

·       Open a ticket with the cloud provider to have an engineer on standby

4. Step-by-Step Procedure — Instance Type Change to cx8xlarge

Phase A — Stop the Instance

1.      Log into the AWS Console and navigate to EC2 → Instances.

2.      Locate the target Versa instance for your region.

3.      Select the instance → Actions → Instance State → Stop.

4.      Wait for the instance state to show Stopped before proceeding.

5.      Confirm that traffic is fully on the other Versa instance and no issues

Phase B — Change Instance Type to required instance size.

6.      With the instance in Stopped state, select it.

7.      Click Actions → Instance Settings → Change Instance Type.

8.      Select cx8xlarge from the instance type dropdown.

9.      Click Apply to save the change.

10.  Confirm the instance type now shows cx8xlarge in the instance details panel before starting.

Phase C — Start the Instance and Validate

11.  Click Actions → Instance State → Start.

12.  Wait for the instance to reach Running state and pass both status checks (2/2).

13.  Confirm the instance type shows cx8xlarge in the instance details.

14.  Validate Versa application health — confirm services are up and traffic is passing.

15.  Check CloudWatch metrics for CPU, memory, and network to confirm normal behavior.

Phase D — Return-to-Service Gate

NOTE: Do NOT return a Versa node to service until ALL of the following are confirmed.

·        Instance type confirmed as cx8xlarge in AWS Console

·       Both EC2 status checks passing (2/2)

·       Versa interfaces present and operational

·       Traffic passing normally through the instance

Use the Post-Change Validation Checklist (Section 5) as the gating criteria.

 

5. Post-Change Validation Checklist

Complete ALL items before marking the change as complete.

 

·        Instance type confirmed as cx8xlarge in AWS Console

·       Both EC2 status checks passing (2/2)

·       Versa services confirmed UP (no service errors)

·       Interfaces present and operational after restart

·       Traffic passing normally through the instance

·       CloudWatch/monitoring tool metrics reviewed — no anomalies in CPU, memory, or network

·       No active alarms triggered post-change

·       Notify NOC team that changes is complete

·       Log the upgrade status in the change management system

·       Document any issues encountered and resolutions applied

6. Failure Conditions and Escalation Triggers

Condition

Action

Instance fails to reach Running state after start

Stop immediately, revert instance type to original (noted in pre-change), start and validate, escalate to Butau / Shaima

Versa interfaces missing after instance start

Do NOT return to service; escalate immediately

Both EC2 status checks not passing after 10 minutes

Escalate to Core Team and NOC to bring in additional resource

Traffic not passing after change

Escalate immediately; initiate rollback if needed

Configuration drift detected after template push

Enforce template-only policy; remove local overrides

 

6.1 Rollback Procedure

16.  Stop the instance immediately.

17.  Revert the instance type to the original value (noted in Pre-Change Checklist).

18.  Start the instance and validate it returns to a healthy state.

19.  Restore from the AMI snapshot taken in Pre-Change if needed.

20.  Escalate to core team immediately.
